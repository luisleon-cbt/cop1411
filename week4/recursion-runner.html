Things to notice

      
    
        
  • Every call gets its own frame with its own boxes. Four calls to power mean four separate exp boxes, and none of them overwrites another.
    • 
        
  • The call stack works like the van from week 2: the last frame pushed is the first one popped.
    • 
        
  • A recursive function needs a base case, and every call must move toward it. Without one the stack grows until Python stops the program with RecursionError, which is Python's stack overflow.
    • 
        
  • fib repeats work: fib(6) makes 25 calls because it computes fib(2) five times. Tower of Hanoi needs 2 to the power n minus 1 moves, and n rush orders have 2 to the power n possible loads. Recursion makes these short to write, not cheap to run.
    • 
        
  • When the recursive call is the very last step of a function it is called tail recursion; Python gives it no special treatment, so it still uses one frame per call.
