The call stack tower

Call a dispatch toolkit function and watch its frame rise, its parameters and locals live inside it, and its return value fly back down to MAIN. A frame is the box of memory Python builds for one call; when the call returns, the frame and everything inside it are gone.

How to use this lab

  1. Under Pick a call, choose a function and its arguments. The code panel shows toolkit.py and the call MAIN makes.
  2. Press Step to run one line. On the scene, a frame rises on the MAIN floor when the function is called, cards appear for its parameters and locals, and the return value flies back down.
  3. Press Step back to see a step again, or Run to play every step. Try find_package and sort_by_weight to watch the shelf.
  4. Turn on Copilot's refactor and run the same call. Each function has one bug; a coral return value means the test named in the narration catches it.
  5. Scroll down to Try it, edit toolkit.py, and press Run there to run real Python against five tests.

    Things to notice
    
      
      
        
    • The parameter cards appear only after the call and vanish at the return. That is scope: a name lives inside the frame that created it.
      • 
        
    • zone returns from the first True branch. The lines after it never run for that call.
      • 
        
    • find_package stops at the first match. return -1 only runs when the loop finishes with no match.
      • 
        
    • Bubble sort on 12, 3, 20, 50, 45 makes 4 passes, 10 comparisons, and only 2 swaps. The reversed list needs 10 swaps.
      • 
        
    • Copilot's price returns the right number for package 0001 and the wrong number for 0005. One passing test proves nothing; the test that can fail is the one that matters.
