How to use this lab

  1. Look at the board. MAIN is the program; the five boxes are functions, each with its parameters in parentheses. The two racks on the right are lists: the weights (12, 3, 20, 50, 45) and the tracking numbers. Click a box to read its def line.
  2. Under Call a function below, pick price, keep weight 12 and miles 8, and press Call. Then press Step: a gold packet carries the arguments into the box, the parameters appear on the local rack, the body runs, and a green packet brings the return value back to MAIN.
  3. Keep pressing Step to the end (or press Run). Watch the Live state: the local variables exist only while the function runs, then disappear. That is scope.
  4. Call zone with a city, and manifest_total with the list. Press Step back whenever you want to see a step again.
  5. Call find_package with a tracking number: the search lights one rack chip at a time until it finds a match (it returns the index) or runs out (it returns -1). Try PP-2026-0009, which is not on the list.
  6. Call sort_by_weight and watch bubble sort compare neighbors pair by pair. Count the passes, the comparisons, and the swaps in the counters, then try your own weights.
  7. Press Copilot's refactor and call the same functions again. Each Copilot version has one bug: a coral packet brings back a wrong value (or an IndexError), and the narration names the test that catches it, for example price(60, 14, True) expecting 59.00. Find all five.

Things to notice

      
    
        
  • The parameters (weight, miles, fragile) are new variables that exist only inside the function. They get their values from the arguments at the moment of the call.
    • 
        
  • return hands one value back to MAIN and ends the function. print only shows text on the screen; a function that prints instead of returning gives MAIN nothing to store.
    • 
        
  • After the call, the local variables are gone. Using one in MAIN gives NameError: name 'p' is not defined.
    • 
        
  • Linear search checks the items in order and returns the index at the first match. It returns -1 for "not found", because no real index is negative.
    • 
        
  • Bubble sort on five items always makes 4 passes and 10 comparisons; the number of swaps depends on the order you give it. 12, 3, 20, 50, 45 needs only 2 swaps.
    • 
        
  • Copilot's refactor looks like the toolkit and passes many calls. price(12, 8, False) gives 16.10 in both versions; only price(60, 14, True) shows the missing surcharge. Pick tests that reach every branch.
